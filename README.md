# LabDAQ

面向 **Data Translation DT9837C-BNC** 的中文桌面数据采集软件，以可靠记录、清楚读数和方便取数为目标。项目正在开发，尚未提供可供用户安装的首版桌面软件。

## 开发方向

采用 **Rust 独立采集核心 + PySide6 / Qt 桌面界面**。采集核心负责输入、采集状态和原始写盘，界面负责配置、控制和显示。软件保留原始电压与采集配置，调零、单位换算和显示滤波不覆盖原始记录。

当前面向一台 DT9837C 的四路模拟输入，逐步覆盖该设备适用的 QuickDAQ 功能。最终运行不依赖原厂专用驱动、SDK 或 QuickDAQ。

目前已贯通采集、记录、回看、统计与导出的日常流程，并加入基础 AO 输出。一般功能使用软件模拟信号开发；AO 已通过物理回接 AI0 做短时功能验证。用户已用信号发生器和示波器评估当前测量精度，结论是当前实验需求下无需调整校准或增加软件补偿。

## 当前状态

- AO 支持直流、正弦、方波和三角波，±3 V、10–96 kS/s 独立更新率；真实 USB 连接后可独立启停，不要求 AI 开始预览，AI 停止采集或 AO 停止归零互不影响，明确断开设备或关闭核心时才停止 AO。关闭 GUI 后核心继续输出，重开恢复状态；配置加载不会自动输出。2026-10-20 已完成低幅值 AO→AI0 回环及四通道最高速采集并行短测，未做精度校准。
- 已接通 Rust 独立 USB 输入、电信号模拟、原始记录和界面重连。DT9837C 使用 WinUSB/libusb，不加载原厂 SDK；关闭或强制结束 GUI 后，核心继续记录，重开可接回同一组。
- 实机已完成 AI3 的 STM32 直流/正弦输入、采样率边界短采集，以及 GUI 强制退出后的续录。四通道最高采样率短采集通过，但只有 AI3 接入了已知信号；这些检查不属于精度校准或小时级稳定性验证。
- 开发测试保留 Python 协议模拟和有限类型的 HPF 文件输入，正式采集页不显示这些来源入口；HPF 只读回看、CSV/TXT 导出和基础信号分析保持可用。旧 Python 模拟和 HPF 输入尚不支持 GUI 退出后续录。
- 记录按“通用目录/实验名/工况-序号”创建原生记录组，工况序号默认从 1 开始并在每组正常收尾后递增，也可手动修改。时长 0 为手动，正秒数按实际采样率四舍五入到整数帧，到点结束记录并返回预览；Rust 核心在 GUI 断开后仍会自动结束。采集页的实验名、当前工况和序号随记录及 JSON 配置保存，并在核心重连后恢复。记录库可编辑已收尾组的描述信息，不改目录、组号、原始波形或结束状态。
- 通道配置支持测点号、方向、工程单位偏移，以及对启用通道批量设置单位、量程、耦合和 IEPE。工程偏移在扣零点、灵敏度换算和极性处理后应用，不改原始电压，也不是仪器校准。
- 日常记录、回看、统计与导出流程已贯通，已有记录库搜索、精确定位、通道与区间选择、多通道统计、区间导出 CSV/TXT、PNG 存图及单步撤销调零。此前已补齐暂停/继续记录、实时与回看双游标、相对/绝对时间及样本号横轴、每通道独立的近一秒读数模式与小数位设置、记录库多组批量导出。暂停期间预览继续，恢复后保留时间缺口，定长仅累计实际记录帧数。
- 多组只读比较支持不同采样率和非连续物理通道、相对时间/绝对电脑时间/样本号、手动样本零点、显隐与颜色、按单位分图及跨图联动游标。比较不重采样、不填补暂停；可保存/恢复比较布局，导出当前窗口的长表 CSV/TXT 和 PNG。每组最多读取 200,000 帧，总通道值不超过 2,000,000，避免长记录整体载入内存。上述新功能使用模拟记录验证，未做本轮实机测试，尚不代表与全部 QuickDAQ Base 功能等价；操作见[用户使用指南](docs/用户手册/user-guide.md)。
- 已卸载 QuickDAQ/Open Layers，并通过物理断电重连后的独立 RAM 固件加载和连续采集。Windows 的冷态和运行态两个 USB 身份都需要 WinUSB，冷启动需要单独准备的本地固件资源。桌面软件打包、小时级运行及核心故障恢复仍待完成。

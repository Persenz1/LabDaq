## 1. 底层 USB 通信模型与端点映射

DT9837C 在运行时枚举为一个具备单一配置与单一接口的 USB 高速外设，分配有 5 个独立的 Bulk 传输端点：

| 端点地址 | 传输方向 | 传输类型 | 典型数据包大小 | 职能定义 |
| :---: | :---: | :---: | :---: | :--- |
| `0x01` | 主机 $\to$ 设备 (OUT) | Bulk | 64 字节 | 下发控制命令包（如采样启动、量程配置、时钟设置） |
| `0x81` | 设备 $\to$ 主机 (IN)  | Bulk | 64 字节 | 回读命令应答包及寄存器回读值 |
| `0x82` | 设备 $\to$ 主机 (IN)  | Bulk | 512 字节 | 连续流式传输 24 位 ADC 原始采样码值流 |
| `0x06` | 主机 $\to$ 设备 (OUT) | Bulk | 512 字节 | 连续流式传输 24 位 DAC 模拟输出波形数据块 |
| `0x88` | 设备 $\to$ 主机 (IN)  | Bulk | 64 字节 | 异步接收设备硬件状态、FIFO 溢出及欠载中断事件 |

## 2. CY22150 锁相环采样时钟推导

DT9837C 使用 Cypress CY22150 可编程数字锁相环生成 ADC 主采样时钟。以板载 $48\text{ MHz}$ 晶振为基准源，通过可编程分频系数实现采样率调节。

### 时钟分频计算公式

$$\text{Fs} = \frac{48\,000\,000 \times P_{\text{total}}}{Q_{\text{total}} \times \text{DIV1} \times \text{ticks} \times \text{divider}}$$

- $\text{ticks}$ 参数：
  - 低速模式（$\text{rate} \le 52,734\text{ Hz}$）：$\text{ticks} = 512$；
  - 高速模式（$\text{rate} > 52,734\text{ Hz}$）：$\text{ticks} = 256$。
- $\text{divider}$ 参数：由控制寄存器 0（Reg 0x00）的分频字段配置（1、2、4、8、16、32、64、128）。

## 3. 早期离线协议模拟器设计

在无物理硬件接入的开发阶段，设计了内存级协议模拟链路（`SimulatedTransport` 与 `firmware.py`），用于闭环验证主机控制命令的正确性：

```text
主机采集层 (DaqSession)
  │
  ├── 构造 64 字节小端命令包
  ▼
协议模拟器 (SimulatedTransport)
  ├── 状态机解码：解析寄存器写入、量程、时钟分频
  ├── 数学信号生成：模拟正弦、方波、阶跃与滑动载荷
  ├── 24 位量化编码：转换为 24-bit Offset Binary 字节流
  ▼
主机接收端
  ├── 丢弃启动前 39 Scans 滤波器群延迟
  └── 码值还原为真实物理电压并推送显示
```

### 固件加载模拟器 (`BootloaderSimulator`)

基于 `labdaq/firmware.py` 实现对 `DTFX2LDR_FW.c` 和 `DT9837A_FW.c` 数组的离线解析：
1. 校验 Intel HEX 记录长度（60 条辅助加载记录，1035 条主固件记录）；
2. 验证针对 `0x7F92` 和 `0xE600` CPUCS 寄存器的复位时序；
3. 校验基于地址 `0x1B3F` 的外部 RAM（Request 0xA3）与内部 RAM（Request 0xA0）的分段写入逻辑。

## 4. 异常处理与状态监控机制

- **FIFO 溢出处理**：当端点 `0x88` 捕获到状态码 `5`（`DataOverrun`）时，系统立即中断当前连续流盘并标记记录终止原因；
- **群延迟丢弃**：Delta-Sigma ADC 的 FIR 降采样滤波器具有 39 个扫描周期（39 Scans）的固有建立群延迟，主机必须丢弃每次启采后的首 39 帧，确保写入文件的数据全为稳态值。

---

## 5. 早期工位测试准备事项记录

初次返回工位时的关键实测任务：
1. 原厂驱动已知输入基线核验：使用示波器和信号发生器确认硬件信号通路；
2. 独立热设备识别与 EEPROM 寄存器只读核验；
3. 四通道小信号短采样与停采重启测试；
4. 物理断电重插后的双 PID 冷启动及重连验证；
5. 原厂路径与独立路径相同输入下的 ADC 原始码值逐点比对。

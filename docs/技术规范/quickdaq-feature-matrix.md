## 1. 概述与比对基线 (Overview & Baseline Definition)

本技术规范旨在客观、严密地评估与对比 LabDAQ 数据采集软件与 Data Translation QuickDAQ 在 **DT9837C-BNC 动态信号采集仪** 硬件平台上的技术特性、功能覆盖、信号处理算法与系统架构边界。

### 1.1 硬件仪器与软件基线版本
- **测试与适配硬件**：Data Translation DT9837C-BNC（USB 2.0 高速动态信号采集仪，4 路 24 位同步 AI，1 路 24 位 AO）；
- **原厂软件参考基线**：QuickDAQ 3.7.0.49（带 FFT Analysis Option 模块，底层驱动依赖 Open Layers Device SDK 7.0.0.9）；
- **LabDAQ 软件基线**：LabDAQ 1.0.0（采用 Rust 独立采集核心 + PySide6 工业级界面 + 本机 Agent API 自动化接口）。

### 1.2 核心架构对比

```text
┌─────────────────────────────────┐        ┌─────────────────────────────────┐
│     QuickDAQ 3.7 (原厂单体架构)    │        │       LabDAQ 1.0 (解耦双进程)    │
├─────────────────────────────────┤        ├─────────────────────────────────┤
│ • 单进程 GUI 绑定驱动调度循环   │        │ • Rust 后台守护核心 (labdaq-core)│
│ • 界面卡顿或重绘易导致 FIFO 溢出│        │ • 200,000 扫描帧环形缓冲区      │
│ • 专有 HPF 二进制存储格式       │        │ • 界面退出/崩溃后台无损持续流盘 │
│ • 封闭图形界面，无原生无头 API  │        │ • 开放 IEEE 754 raw.f64 + JSON  │
│ • 依赖原厂完整软件套件安装      │        │ • 本机 Agent CLI / Python SDK   │
└─────────────────────────────────┘        └─────────────────────────────────┘
```

## 2. 详细功能基线对照矩阵 (Detailed Comparison Matrix)

### 2.1 模拟输入 (AI) 与前端调理特性

| 功能特性分类 | QuickDAQ 3.7.0.49 原厂能力 | LabDAQ 1.0.0 实现方案 | 架构差异与技术实现原理 |
| :--- | :--- | :--- | :--- |
| **通道数量与子集** | 4 路单端同步模拟输入，BNC 接头；支持逐通道启用/禁用。 | 4 路单端同步模拟输入；支持任意升序子集选择（例如 `[0, 2]` 或 `[1, 2, 3]`）。 | 两者一致。LabDAQ 在硬件层面仅解交织所选通道，未启用通道不占用 USB 传输带宽。 |
| **ADC 分辨率与类型** | 24 位 Delta-Sigma A/D 转换器，每通道独立 ADC 同步转换。 | 24 位 Delta-Sigma A/D 转换器，每通道独立并行转换。 | 两者一致。采用无符号偏移二进制（Offset Binary）编码。 |
| **硬件采样率范围** | $195.313\text{ Hz} \sim 105,469\text{ Hz}$ 连续可设。 | $195.313\text{ Hz} \sim 105,469\text{ Hz}$ 连续可设，并提供标准常用标称档位。 | 两者一致。基于 Cypress CY22150 锁相环（PLL）分频；LabDAQ 在采样率 $> 52,734\text{ Hz}$ 时自动切换高频 256 Ticks 模式。 |
| **FIR 抽取滤波器群延迟** | 固件内部补偿或由驱动统一维护。 | 驱动层硬件级补偿，启动采集时严格丢弃前 39 个扫描周期（`GROUP_DELAY = 39`）。 | LabDAQ 确保传递给环形缓冲与存储文件的第一个点即为滤波器完全建立后的稳态采样值。 |
| **输入电压量程** | 双量程可选：$\pm 10\text{ V}$（增益 $\times 1$）与 $\pm 1\text{ V}$（增益 $\times 10$），逐通道独立配置。 | 双量程可选：$\pm 10\text{ V}$ 与 $\pm 1\text{ V}$，逐通道独立配置，支持批量一键设置。 | 两者一致。通过写入 DT9837C 控制寄存器 2 的 Bit 4～7 硬件增益位实现。 |
| **输入耦合方式** | AC 耦合（标称 $1.0\text{ Hz}$ 高通截止）与 DC 耦合，逐通道独立配置。 | AC 耦合与 DC 耦合，逐通道独立配置，支持批量应用。 | 两者一致。写入控制寄存器 2 的 Bit 0～3。 |
| **IEPE 传感器激励源** | 内置恒流源供电，逐通道开关控制。 | 内置 $4\text{ mA}$ 恒流源供电，逐通道独立控制。 | LabDAQ 增加硬件保护时序：在切入 DC 耦合前强制先切断该通道的恒流源，防止瞬态电流损坏传感器。 |
| **测速计/计数器通道** | 界面选项显示通用系列参数。 | 严格不暴露 Tachometer / Counter 虚拟通道。 | **硬件真实性界定**：DT9837C 硬件底层不包含物理 Tachometer 通道（仅 A/B 系列支持）。LabDAQ 准确反映硬件物理边界。 |

### 2.2 传感器管理与调零机制

| 功能特性分类 | QuickDAQ 3.7.0.49 原厂能力 | LabDAQ 1.0.0 实现方案 | 架构差异与技术实现原理 |
| :--- | :--- | :--- | :--- |
| **工程单位配置** | 支持 $\text{N}$、$\text{mV/EU}$、$\text{EU Offset}$、测点号（Point #）及方向（Dir）配置。 | 支持自定义物理单位、灵敏度（$\text{mV/EU}$）、工程偏移、测点编号及三向测点方位。 | 两者一致。LabDAQ 额外提供批量通道参数复制与多通道配置快速同步。 |
| **调零基准扣除 (Zeroing)** | 提供通道偏置调零功能，计算零点电压并在显示中扣除。 | 提取最近最多 $1.0\text{ 秒}$ 原始电压均值作为 $V_{\text{zero}}$，支持单步无损撤销调零。 | **存储与显示解耦**：LabDAQ 的软件调零仅作用于界面呈现和派生导出，底层 `raw.f64` 始终保存真实绝对物理电压。 |
| **极性翻转与工程偏移** | 换算公式中支持偏置与极性设置。 | 支持单通道极性反转（$\times -1$）与工程单位加法偏移（$\text{Offset}_{\text{eng}}$）。 | 换算管线标准化：扣零点 $\to$ 灵敏度增益换算 $\to$ 极性翻转 $\to$ 工程单位偏移。 |

### 2.3 数据流盘、存储与会话组织

| 功能特性分类 | QuickDAQ 3.7.0.49 原厂能力 | LabDAQ 1.0.0 实现方案 | 架构差异与技术实现原理 |
| :--- | :--- | :--- | :--- |
| **原始数据存储格式** | 专有 HPF 二进制文件格式（Data Translation 专有结构）。 | 开放双精度小端二进制文件 `raw.f64`（IEEE 754 `<f8`，无头裸流）。 | LabDAQ 格式无需任何专用 SDK，支持通过 Python NumPy、MATLAB、C/C++ 以零拷贝方式直接映射读取。 |
| **元数据存储与版本化** | 嵌入在 HPF 专有数据块中（0x7000、0x8000 等）。 | 独立标准化 `metadata.json`，两阶段原子写替换保护。 | 保证全量配置、通道映射、时钟信息与事件日志的通用可读性与防损坏能力。 |
| **目录组织与命名** | 用户指定基础文件名，按序号或日期自动递增单个 HPF 文件。 | “一实验一独立文件夹”规范：`<root>/<experiment>/<condition>-<group>/`。 | 杜绝文件误覆盖；记录库支持实验名、工况、试件与备注的结构化索引与维护。 |
| **记录控制 (暂停与继续)** | 支持 Pause（暂停）与 Stop（停止）。 | 支持录制期间暂停与继续，并在元数据中生成分段清单（`recording_segments`）。 | LabDAQ 在暂停期间硬件时基保持连续，时域回看中以断线真实呈现时间缺口，不进行人工插值。 |
| **断电/崩溃防护机制** | 单进程崩溃可能导致未封顶的 HPF 文件损坏无法加载。 | 双进程隔离：GUI 关闭或崩溃后台核心无损续录；会话恢复器可根据文件长度恢复未封顶帧。 | 极大提高长时间工业监测与不可重现冲击试验的可靠性。 |
| **原厂 HPF 格式兼容性** | 原生读写全部 HPF 文件。 | 内置高性能 HPF 解析引擎，支持 Double 类型波形数据的免原厂驱动只读解析与回放。 | 支持载入历史 QuickDAQ 实验文件并在现代化界面中复现分析。 |

### 2.4 示波器呈现、测量游标与多组比对

| 功能特性分类 | QuickDAQ 3.7.0.49 原厂能力 | LabDAQ 1.0.0 实现方案 | 架构差异与技术实现原理 |
| :--- | :--- | :--- | :--- |
| **时域波形渲染** | 基于传统 GDI/GDI+ 绘图，高采样率长窗口下存在刷新卡顿。 | 基于 PyQtGraph 硬件加速渲染，支持平滑缩放、平移与滚动冻结。 | 典型刷新率为 $30\text{ Hz}$，时域监视窗口默认 $8.0\text{ 秒}$，最长可平滑呈现 $60.0\text{ 秒}$。 |
| **统计指标面板** | 显示均值、最小、最大、有效值（RMS）、标准差。 | 实时统计卡片支持最新值、首值、均值、最小、最大、RMS、总体标准差与峰峰值。 | 提供 $0 \sim 9$ 位动态小数位精度调节，并在幅值临近满量程时给予黄色告警。 |

| **多组实验叠加比对** | 需分别导入多个文件，时间轴对齐操作较为繁琐。 | 专用“多组数据比对”工作台，支持加载多组历史记录同图或按单位分图比对。 | **保真不重采样**：各组保留各自真实的物理时钟，支持相对时间、电脑绝对时钟与样本点 3 种对齐模式。 |

### 2.6 频域分析与数字滤波算法

| 功能特性分类 | QuickDAQ 3.7.0.49 原厂能力 | LabDAQ 1.0.0 实现方案 | 架构差异与技术实现原理 |
| :--- | :--- | :--- | :--- |
| **单通道频谱分析** | Spectrum、Auto Spectrum、PSD；支持 dB/线性缩放。 | 单边峰值幅度谱（Peak Spectrum）与单边功率谱密度（PSD）。 | **能量严格守恒**：经过窗函数相干与功率增益补偿，矩形窗下全谱数值积分严格满足 Parseval 能量定理。 |
| **窗函数支持** | Rectangular、Hann、Hamming、Blackman、FlatTop 等。 | Rectangular、Hann、Hamming、Blackman、FlatTop。 | 采用标准周期对称窗，提供良好的旁瓣抑制与幅值精度。 |
| **双通道频响分析 (FRF)** | Advanced FFT 选项支持 H1/H2/H3 估计与相干函数输出。 | 内置基于 Welch 方法的标准 H1 频响传递函数与幅值平方相干函数（$\gamma_{xy}^2$）。 | 要求至少 2 个重叠数据段以保障相干系数的统计有效性，低信噪比频点安全输出 `NaN`。 |

## 3. 架构优势与工程权衡总结 (Architectural Evaluation)

### 3.1 核心技术优势
1. **数据链追溯性**：坚持将原始物理电压作为唯一持久化基础，将灵敏度、零偏与滤波作为元数据和派生计算，保证了科研实验在数年后依然具备完全复现与重分析的能力；
2. **工业级鲁棒性**：Rust 守护进程保障高采样率下的连续吞吐与无丢包落盘，GUI 退出或系统重绘对底层硬件流完全透明；
3. **现代数据生态契合度**：摒弃专有封闭的文件格式与接口封装，全面对接 JSON、NumPy `<f8`、Pandas 及 Python 科学计算生态；
4. **轻量与免配置**：安装包内聚原厂驱动静默部署，运行无需外部 Python、Conda 或编译工具链环境。

### 3.2 适用场景建议
- **LabDAQ 推荐场景**：结构动态冲击与模态试验、高采样率长周期连续监测、需集成到自动化脚本与 Agent 工作流中的硬件在环（HIL）测试系统；
- **QuickDAQ 适用场景**：依赖原厂旧版 XML 配置文件继承的历史实验室环境、需直接与 Excel 宏深度绑定的工控机单机离线浏览。

# 未来功能开发规划

下一阶段以离线数据分析为主，先完善已有记录的查看和计算，再考虑实时分析。1.0 的采集、原始记录、AO、回看、游标、导出和本机 API 继续保留。

## 已知问题与限制（1.0）

实时显示每通道最多缓存 200,000 个原始采样点，窗口上限为 `min(60, 200000 / 实际采样率)` 秒。四路最高速 105468.75 S/s/通道时，上限约 1.896 秒；输入更长时间会被控件限制，重开界面后也按实际采样率重新计算。这是当前显示容量的限制，不影响全速采集、原始记录或记录时长，本轮不修改。

后续若需在最高速下显示 10 秒或 60 秒，考虑增加保留峰值的显示历史；显示数据与原始记录分开处理，不直接放大原始点数后逐帧重绘。

## 开发原则

- 分析读取原生记录或受支持的 HPF，不修改原始电压、采样率和记录时保存的传感器参数。
- 已有的 `processing.py`、统计、记录库及比较代码先核对再复用，不另建采集核心或分析服务。
- 结果能说明使用了哪些通道、时间段、单位和处理参数，并能导出后复算。
- 先做好少量常用功能。下面是开发顺序，不是交付日期或已完成承诺。

## 第一阶段：单组记录分析

从回看页选择通道和时间段，进入分析；返回时保留浏览位置。原始 V 与工程量分别标明，默认沿用记录中的换算配置。

| 功能 | 计划内容 |
| --- | --- |
| 区间统计 | 完善最小值、最大值、均值、峰峰值、RMS 和总体标准差，支持多通道表格复制与导出。 |
| 幅度谱 | 提供单边峰值幅度谱，明确区别于 RMS、功率谱及 PSD；显示采样率、点数、频率间隔和窗函数。 |
| PSD | 提供单位平方/Hz 的结果，补充分段长度、重叠率和平均设置，避免把幅度谱直接称为功率谱。 |
| 频域游标 | 查看频率、幅值、主峰及指定频带的积分结果；间隔倒数与自动基频识别分开标注。 |
| 分析导出 | 导出数值、单位和参数，支持保存图像；分析结果与原始记录分开保存。 |

记录中的暂停缺口不能补零后当成连续数据做 FFT。选区跨缺口时，应选择一个连续段或明确按段分析。长记录按需要读取，统计在后台分块计算，可取消且不展示未完成结果。

## 第二阶段：滤波与多组比较

滤波优先用于离线派生数据，提供低通、高通、带通和带阻，显示截止频率、阶数和响应。明确区分因果滤波与双向零相位滤波，说明启动和边缘影响；不把软件滤波当作硬件抗混叠或校准。

恢复并整理已有记录库与多组比较入口。支持按实验和工况查找记录、勾选叠加、通道显隐、按单位分图，以及手动选择真实样本作对齐点。不同采样率的曲线各用自己的时间点，默认不重采样，不强行拼成公共网格。

分析配置可保存并重新加载，包括记录、通道、选区、单位、滤波和频谱设置。先复用现有 JSON 配置方式。

## 第三阶段：参考/响应分析

针对具有参考激励和响应通道的试验，先提供 H1 频响、互谱和相干函数，再按实际需要补 H2/H3、相位和冲击平均。

- 参考与响应必须来自可比较的同步采样区间，保留单位和测点方向。
- Welch 分段、窗、重叠率和平均次数应可见；至少包含两个有效分段，避免用单段相干等于 1 误导判断。
- 无能量频点和无效数据保留为无效值，不填造响应曲线。
- 冲击流程后续再加入接受/拒绝、累计平均及对应窗函数，使用真实激励与响应做对照。

## 后续扩展

积分到速度/位移、dB 标度、THD/SNR、UFF 和复数频响交换，在单位定义、算法和实际用途明确后再加入。高级触发、扫频/噪声输出及多设备同步另行安排，不与基础分析同时展开。

分析函数稳定后，通过现有 Python API 和 JSON CLI 暴露相同计算入口，供 Agent 调用。界面与接口使用同一套算法和参数定义。

## 验证方式

使用已知正弦、直流、噪声及带暂停缺口的合成记录核对数值；幅度、RMS、PSD 积分和滤波响应应与各自数学定义一致。频响用已知系统和真实参考/响应记录对照。界面只验证选区、参数、单位及导出是否正确传递，不重复堆叠同一算法测试。

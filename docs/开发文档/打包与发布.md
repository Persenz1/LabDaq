本指南详细阐述 LabDAQ 1.0 生产发布包的自动化构建流程、打包规格定义、原厂 OEM 驱动集成机制以及上线前工程验收清单（Release Checklist）。

## 1. 发布构建架构全景

LabDAQ 采用单一一体化安装包发行形态（`LabDAQ-<版本号>-windows-x64-setup.exe`），彻底免除最终用户的 Python、Conda、Rust 或第三方驱动配置成本。

```text
                                  +---------------------------------------+
                                  |     1. 编译 Rust 独立采集核心         |
                                  |     cargo build --release -p labdaq-core
                                  +---------------------------------------+
                                                      │
                                                      ▼
+---------------------------------------+     +---------------------------------------+
|        3. 提取原厂 OEM 驱动程序       |     |     2. PyInstaller 双程序冻结封装     |
|   DataAcqOMNI_V7.8.9.zip 内部提取      |     |     - LabDAQ.exe (GUI 无控制台)      |
|   OEM Setup/SetupOem.exe              |     |     - LabDAQ-api.exe (CLI 有控制台)   |
|   (微软官方签名内核驱动与运行库)       |     |     - 内嵌 docs/用户手册/             |
+---------------------------------------+     +---------------------------------------+
                   │                                          │
                   └───────────────────┬──────────────────────┘
                                       │
                                       ▼
                       +-------------------------------+
                       |    4. Inno Setup 6 封装编译    |
                       |    - 注入 SetupOem.exe 静默安装|
                       |    - 生成 Windows x64 安装程序 |
                       +-------------------------------+
                                       │
                                       ▼
                       +-------------------------------+
                       |  dist/LabDAQ-1.0.0-windows-   |
                       |         x64-setup.exe         |
                       +-------------------------------+
```

## 2. 构建先决条件 (Prerequisites)

在执行发布构建前，请确保构建机器满足以下环境要求：
1. **Windows 10/11 x64 操作系统**。
2. **已配置的 Python 3.12+ 虚拟环境**：
   * 已安装 `requirements.txt` 中的全部运行库。
   * 已安装 PyInstaller（版本推荐 `6.22.3`）：`pip install pyinstaller==6.22.3`。
3. **Rust 2024 工具链** 与 **Visual Studio 2022 C++ 生成工具**。
4. **Inno Setup 6 编译器**：
   * 默认安装路径通常为 `C:\Program Files (x86)\Inno Setup 6\ISCC.exe`。
5. **原厂驱动归档包**：
   * 确保项目本地存在 `resources\vendor\installers\DataAcqOMNI_V7.8.9.zip`。

---

## 3. 一键自动化构建流水线

项目在 `tools/build-release.ps1` 提供了完整的一键自动化构建脚本。在项目根目录下打开 PowerShell 7 终端执行：

```powershell
.\tools\build-release.ps1 -PythonPath "C:\path\to\your\venv\Scripts\python.exe"
```

* **可选参数 `-IsccPath`**：若 Inno Setup 安装在非默认目录，可通过该参数显式传入 `ISCC.exe` 路径。
* **构建产物**：成功执行后，安装程序将输出至 `dist/LabDAQ-<版本号>-windows-x64-setup.exe`。

## 4. 关键打包规范与配置文件解析

### 4.1 PyInstaller 规范 (`tools/LabDAQ.spec`)

`tools/LabDAQ.spec` 负责将 Python 代码、Qt 动态库与 Rust 二进制打包为自包含程序集：
1. **双可执行文件生成**：
   * **`LabDAQ.exe`**：设置 `console=False`，作为图形化桌面主客户端入口。
   * **`LabDAQ-api.exe`**：设置 `console=True` 并剥离 Qt 运行时钩子，作为高效轻量的控制台自动化接口。
2. **离线用户手册嵌入**：
   * 规则：`datas=[(str(root / "docs" / "用户手册"), "docs/用户手册")]`。
   * 确保用户在无网络离线环境下仍可通过 `_internal\docs\用户手册\` 查阅完整的操作与 API 指南。
3. **动态链接库依赖隔离**：
   * `a.binaries = [item for item in a.binaries if Path(item[0]).name.lower() != "icuuc.dll"]`
   * Qt 6.12 依赖 Windows 系统内置的 ICU 字符集 API。此过滤规则可彻底排除开发机 PATH 环境变量中由第三方软件（如 Conda/Poppler）引入的冲突 `icuuc.dll`，避免在目标机上引发 `QtCore.dll` 符号缺失崩溃。

### 4.2 Inno Setup 安装包定义 (`tools/LabDAQ.iss`)

`tools/LabDAQ.iss` 定义了安装向导行为及原厂驱动的静默部署逻辑：
1. **目标路径与权限要求**：
   * `DefaultDirName={autopf}\LabDAQ`：默认安装至系统的 64 位程序目录（`C:\Program Files\LabDAQ`）。
   * `PrivilegesRequired=admin`：安装过程强制请求管理员权限。
2. **静默调用原厂驱动安装程序**：
   * 在向导准备阶段（`PrepareToInstall`），安装程序将原厂 `SetupOem.exe` 释放至系统临时目录并静默执行：
     ```cmd
     SetupOem.exe /s /v"/qn REBOOT=ReallySuppress"
     ```
   * **退出码校验与重启处理**：
     * `0`：驱动安装成功且无需重启。
     * `3010` / `1641`：驱动安装成功，但系统需要重启以完全接管设备；安装向导将引导用户在完成安装后重启计算机。
     * 其他非零退出码：判定为驱动部署失败并终止安装，防止释放不可用的半成品软件。

## 5. 版本发布前验证清单 (Release Checklist)

在正式标记版本发布前，必须依次完成以下 4 个阶段的工程核验：

### 阶段 1：代码与自动化测试核验 (Pre-Build QA)
- [ ] **全量自动化测试通过**：
  - 运行 Rust 核心测试：`cargo test --manifest-path core/Cargo.toml`
  - 运行 Python 全套测试：`pytest tests/ -q`
- [ ] **接口与无头 CLI 回归**：
  - 验证 `LabDAQ-api.exe` 的 `status`、`devices`、`start-acquisition`、`read`、`export` 指令返回合规 JSON。
- [ ] **文档与超链接审计**：
  - 运行文档审计工具，确认全库 Markdown 文件相对链接无死链，且正式文档中无任何机械自辩或防御性免责套话。

### 阶段 2：安装包编译与完整性核验 (Artifact Validation)
- [ ] **一键构建正常结束**：`tools/build-release.ps1` 退出码为 0，无编译警告。
- [ ] **输出目录检查**：`dist/` 目录下生成 `LabDAQ-1.0.0-windows-x64-setup.exe`，安装包尺寸在合理区间（约 150MB～300MB）。
- [ ] **安装包文件内容检查**：
  - 包含 `LabDAQ.exe` 与 `LabDAQ-api.exe`。
  - 包含 `labdaq-core.exe`。
  - 包含 `_internal\docs\用户手册\` 完整目录与 `_internal\docs\开发文档\technical-notes.md`（供桌面界面“打开技术说明”按钮调用）。
  - 包含根目录下的 `使用说明.txt` 与 `THIRD_PARTY_NOTICES.md`。

### 阶段 3：目标物理机全新安装实测 (Clean Target Installation)
- [ ] **原厂驱动静默部署**：在未安装过 LabDAQ 的测试机上运行安装包，原厂驱动静默安装顺畅无报错弹窗。
- [ ] **硬件枚举与就绪**：接入 DT9837C 仪器，Windows 设备管理器中正确识别设备，服务正常挂接。
- [ ] **普通用户权限运行**：从开始菜单启动 LabDAQ，无需 UAC 提权即可正常建立连接并待机。
- [ ] **核心功能链路验证**：
  - 完成四通道 5 kS/s 连续预览。
  - 执行“当前载荷归零”与“撤销调零”。
  - 启动 AO 正弦波输出，并通过 BNC 物理回环接入 AI0 进行回读波形验证。
  - 执行定长 10 秒流盘记录，检查生成文件夹结构、`raw.f64` 字节数与 `metadata.json` 规范性。
  - 执行数据导出，在 Excel 或 Python pandas 中成功读取 CSV 文件。
- [ ] **Agent CLI 连通性**：在终端运行 `LabDAQ-api.exe status`，正确回读系统与采集状态。

### 阶段 4：卸载与持久化安全性核验 (Uninstall Verification)
- [ ] **配置与数据保留**：在 Windows 设置中卸载 LabDAQ，确认 `%LOCALAPPDATA%\LabDAQ` 下的用户配置和 `recordings` 目录下的实测数据得到完整保留，未被误删。
- [ ] **无残留后台进程**：卸载完成后，检查任务管理器中无残留的 `labdaq-core.exe` 僵尸进程。

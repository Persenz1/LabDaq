# 开发环境与源码运行

当前架构为 **原厂 Open Layers 驱动 + Rust 采集核心 + Python / Qt 前端与数据处理**。
已按职责撤回 Rust 桌面、分析、数据文件和旧安装器工程，保留同期核心增强及原厂驱动接入。

## Windows 安装包

复用现有 Python 环境中的 PyInstaller 6.22.3，在项目根目录执行：

```powershell
.\tools\build-release.ps1 -PythonPath D:\DevTools\Conda\envs\agents-py312\python.exe
```

1.0 只发行 Windows x64 安装包，不再生成便携 ZIP。安装包包含 Python、Qt、NumPy/SciPy 和 Rust 核心，并调用完整原厂 OEM 安装程序安装设备驱动及 Open Layers x64 运行库。安装后的程序不依赖开发用 Conda 路径。构建复用现有 Python 环境，不创建环境。

安装版默认程序目录为 `%ProgramFiles%\LabDAQ`，在当前 x64 模式下通常为 `C:\Program Files\LabDAQ`，由安装脚本的 `{autopf}\LabDAQ` 确定。程序自带运行环境，不向安装目录写用户配置或记录。

当前用户配置和运行状态根目录为 `%LOCALAPPDATA%\LabDAQ`。核心自动配置位于 `.runtime\core.profile.json`，连接端点位于 `.runtime\core.json`，主题缓存位于 `.runtime\theme`；目前没有独立的 `config` 子目录。

默认记录根目录为 Windows“文档”目录下的 `LabDAQ\recordings`。`labdaq/paths.py` 通过 `SHGetKnownFolderPath(FOLDERID_Documents)` 读取实际位置，跟随系统重定向，不硬编码 `%USERPROFILE%\Documents`。文件夹在实际记录时创建。自选记录根目录仅在本次会话及接回已有后台时恢复，完全退出核心后重开 GUI 使用默认目录；不宣称自选目录或所有界面偏好均已跨重启保存。

源码版继续使用项目内的 `.runtime` 和 `recordings`；本次不迁移已有配置或测量文件。更换安装目录不改变用户目录，卸载保留用户配置和记录。Qt 6.12 使用 Windows 系统 ICU；打包规格排除 PATH 上其他软件的 `icuuc.dll`，避免不兼容 DLL 导致 QtCore 导入失败。更换核心前须停止记录、采集与输出并关闭界面。

AO 更新率为 10、20、48、96 kS/s 四档，默认 48 kS/s。频率输入上限和提示随档位更新；幅值与偏置组合超限时禁用开始按钮，核心保留独立校验，并在原厂回读实际更新率后再次检查频率。

## 2026-10-26 原厂驱动接通与实机验证

默认真实采集使用 `Source::Vendor` 和 `core/src/vendor_input.rs`：Rust 直接加载 `oldaapi64.dll`、`olmem64.dll`，不经过 Python 或 .NET。`core/src/input.rs` 统一分派原厂和旧 USB 后端；Qt 的物理输入在核心协议中映射为 `vendor`。旧 WinUSB 后端只通过显式 `source = "usb"` 使用，不与原厂 SDK 同时占用设备。

本机已用用户提供的 DataAcq OMNI 7.8.9 `OEM Setup/SetupOem.exe` 安装运行库，官方静默参数为 `/s /v/qn`。普通管理员授权即可，不需要微软开发者账号，不关闭签名强制或 Secure Boot。外层安装启动器未签名，但包内实际驱动包的 `oem108.inf` 验签为 Microsoft Windows Hardware Compatibility Publisher；不能把启动器状态等同于驱动未签名。

安装后实测 Windows 自动采用原厂绑定，旧的 WinUSB/libwdi 绑定不再用于设备：冷态 `VID_0867&PID_9839` 使用 `DT9837aLD_x64`，运行态 `VID_0867&PID_3998` 使用 `DT9837aK_x64`。断电重插已回读确认这两个实际服务，不是只看驱动文件是否存在。未卸载 Windows 的 WinUSB 系统驱动；若其他电脑保留旧绑定，应结束采集后用原厂完整签名驱动包切换并回读，不要求用户配置 WinUSB。

无硬件回归包括核心、桌面 Rust 测试和 31 项 Python 定向测试。实机使用 DC、IEPE 全关、±10 V，完成约 1000.116 S/s 的预览、停止/重启和断电后的再次采集；默认 Qt 和隔离配置的 egui 均完成连接、预览、原生记录和停止，记录为 `source = vendor` 且正常收尾。

AO→AI0 回环以 0.1 V、10 Hz、48 kS/s 短测，稳定段回读约 -0.1016～+0.1009 V，停止后残余绝对值不超过 0.00068 V。记录包含 1869 个完整四通道帧及 AO 启停事件。停止边界出现一次约 -0.204 V 瞬态，稳定段分析不包含该边界，尚未进一步判定其滤波/时序原因；这不是精度校准结论。未接外部信号源的通道只检查有限值，未验证电气精度。

旧 WinUSB 安装器草案已撤回；新的安装发行使用完整原厂 OEM 安装程序，不使用旧 WinUSB 绑定。原厂 SDK 的最高采样率、小时级运行、多设备硬同步和 AO 精度/停止边界的进一步验证仍待完成。

## 环境

- Windows、PowerShell 7。

## 构建与启动

以下命令均在项目根目录执行。根 Cargo workspace 仅保留 core。首次从源码使用独立核心或修改 Rust 源码后，先构建：

```powershell
. .\tools\dev-env.ps1
cargo build --release -p labdaq-core
```

输出为 `target/release/labdaq-core.exe`，构建产物不纳入 Git 仓库。若核心正在运行，先在界面中停止采集并关闭窗口，再重新构建。

默认开发环境已准备好时，运行：

```powershell
.\launch.ps1
```

使用其他现有 Python 环境时，可在 PowerShell 中指定解释器：

```powershell
$DaqPython = Read-Host '输入现有 Python 环境中 python.exe 的完整路径'
.\launch.ps1 -PythonPath $DaqPython
```

需要打开界面后自动开始模拟预览时，使用同一解释器：

```powershell
& $DaqPython -m labdaq --demo
```

界面操作见[用户手册开发稿](../用户手册/user-guide.md)。

当前正式采集页只显示 USB 输入。安装发行不注册模拟和 HPF 采集来源，不开放 `--demo`，并拒绝载入开发输入配置；HPF 只读回看仍是正式功能。源码保留开发输入供回归测试使用。开发阶段的波形参数和输入语义见[力信号输入与模拟开发边界](../功能实现/signal-input.md)。

## 当前实现与验证

### 当前原厂输入

界面选择“DT9837C · 原厂驱动输入”。自动检测通过 Rust 核心和 Open Layers 完成，不先用 PyUSB 排除设备。连接时只打开原厂会话，不开始采集；开始预览/记录时应用通道配置，实际采样率由 Open Layers 回读。停止采集保持设备连接；断开设备释放原厂驱动会话，不声称切断硬件工作电源。关闭活动采集的 GUI 保留核心和记录，关闭空闲 GUI 则释放设备并退出核心。

### 历史：独立 WinUSB 开发路径

以下只适用于显式 `source = "usb"` 的旧后端，不是普通用户的安装步骤。该路径要求 `VID 0867 / PID 3998`（运行态）和 `VID 0867 / PID 9839`（冷启动）都绑定 WinUSB，与原厂 SDK 不能同时占用设备。核心连接后读取 EEPROM subtype，只有 C 型号才继续。

冷启动的两段 RAM 固件从本地归档的 libuldaq 1.2.2 C 数组准备，不从系统安装的原厂程序获取。在项目根目录用选定的 Python 解释器运行：

```powershell
& $DaqPython tools/prepare_usb_firmware.py
```

输出为本地 `resources/firmware/dt9837-ram.json`，不纳入源码仓库。运行核心时工作目录为项目根目录，GUI 启动器已遵循此约定。固件缺失、冷态驱动不匹配或运行态未在原 USB 端口出现时，会明确失败，不转为模拟输入。只加载 RAM，不改 EEPROM 或校准电位器。

旧 WinUSB 后端连接后保持工作电源而不采样，开始预览/记录时启动采集，停止后保留 USB 连接与工作电源，断开时关闭工作电源并释放 USB。PA4 测试使用 AI3、DC、IEPE 关闭、±10 V；采样率使用核心返回的 PLL 名义值。该路径已实测连接时零扫描、重复启停后保持连接，以及断开、重连。

2026-10-19 的实机短测已完成 195.3125、1000.115955 和四通道 105468.75 S/s，GUI 强制退出后的继续记录和重连也已通过。只有 AI3 接了 STM32 信号，其他通道的电气精度未检验。最高速首次同步读取出现过设备 FIFO 溢出，已改为预提交 8 笔异步读取并复测通过；错误记录保留实际终止原因，不伪装为正常完成。小时级运行和核心意外退出恢复仍需后续验证。用户后续已用信号发生器和示波器评估当前精度，结论是满足当前实验需求，不调整校准或增加软件补偿。

同日卸载 QuickDAQ、Open Layers 及 OEM x86/x64 安装项后，物理拔插数采，从 WinUSB 冷态 PID 9839 开始，由 Rust 核心加载两段 RAM 固件并在原端口找到 PID 3998；随后上述三个采样率再次短测通过。最高速记录包含 572313 帧 × 4 通道，AI3 的 10 Hz 信号拟合为约 10.00039 Hz。该频率由设备名义采样率计算，不是外部时基校准。原厂参考资料仍保存在本地资源目录，运行测试未加载原厂 DLL。采集中拔线与小时级运行尚未实测。

### 原有模拟路径

Rust 独立模拟核心负责电压生成、AC 演示模型、24 位量化、原始记录和有界显示缓存。Qt 通过本机回环 TCP 控制核心并取得显示窗口；启动时由系统分配空闲端口，连接信息和随机凭据保存在对应用户数据目录下的 `.runtime/core.json`。重开界面按该端点接回，不再共用固定端口。

2026-10-16 已确认 **2 项 Rust 测试和 40 项 Python 定向测试通过，进程正常退出**。验证包含 GUI 被强制结束后的续录和重连、波形对照、调零、缓存上限及相关记录和界面回归；该结果不代表实机或小时级运行验证。

Rust 测试入口为 `cargo test --manifest-path core/Cargo.toml`，Python 测试位于项目根目录的 `tests/`，使用选定环境的解释器运行 pytest。修改 Rust 后先执行 `cargo build --release --manifest-path core/Cargo.toml`，再运行包含 Rust/Python 进程的测试，避免误用旧核心。Windows 下将每次 pytest 的 `--basetemp` 指向项目内独立的 `.task-tmp` 子目录，不并发共用同一目录；Rust 的 `TEMP`、`TMP` 也指向本次任务子目录，避免系统临时目录的访问权限问题。控制台中文乱码时可在解释器后加 `-X utf8`。按实际修改选择相关测试，纯文档修改无需重跑采集测试。

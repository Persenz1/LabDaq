# 开发环境与源码运行

本页供开发和调试使用。当前尚无供用户安装的桌面软件，以下命令是源码运行方式。

## 环境

- Windows、PowerShell 7。
- 已配置好的 Python 3.12 或更新版本环境。运行依赖见 [pyproject.toml](../../pyproject.toml)，已有验证版本记录见 [requirements.txt](../../requirements.txt)。复用现有环境，不由启动脚本创建环境或安装依赖。
- Rust 工具链，以及 MSVC C++ 构建工具和 Windows SDK。构建命令需在已配置 MSVC 环境的开发者终端中运行。

`launch.ps1` 默认从当前用户的 Conda 环境登记文件查找 `agents-py312`。这是当前开发脚本的默认值，不要求其他开发者使用同名环境；可通过 `-CondaEnvironment` 指定已有 Conda 环境，或通过 `-PythonPath` 指定现有环境的 Python 解释器完整路径。

## 构建与启动

以下命令均在项目根目录执行。首次从源码使用独立核心或修改 Rust 源码后，先构建：

```powershell
cargo build --release --manifest-path core/Cargo.toml
```

输出为 `core/target/release/labdaq-core.exe`，构建产物不纳入 Git 仓库。若核心正在运行，先在界面中停止采集并关闭窗口，再重新构建。

默认开发环境已准备好时，运行：

```powershell
.\launch.ps1
```

使用其他现有 Python 环境时，可在 PowerShell 中指定解释器：

```powershell
$DaqPython = Read-Host '输入现有 Python 环境中 python.exe 的完整路径'
.\launch.ps1 -PythonPath $DaqPython
```

需要打开界面后自动开始模拟预览时，使用同一解释器：

```powershell
& $DaqPython -m labdaq --demo
```

界面操作见[用户手册开发稿](../用户手册/user-guide.md)。

## 当前实现与验证

### 真实 USB 输入

Rust 核心通过 rusb/libusb 直接访问 DT9837C，不调用 Open Layers DLL。Windows 下 `VID 0867 / PID 3998`（运行态）及 `VID 0867 / PID 9839`（冷启动）都需要绑定 WinUSB；这会使原厂 QuickDAQ 无法使用该设备。首次切换可使用官方 [Zadig](https://zadig.akeo.ie/)，按 USB ID 确认目标，不能按 A/B/C 共用的设备名称判断型号。核心连接后会读取 EEPROM subtype，只有 C 型号才继续。

冷启动的两段 RAM 固件从本地归档的 libuldaq 1.2.2 C 数组准备，不从系统安装的原厂程序获取。在项目根目录用选定的 Python 解释器运行：

```powershell
& $DaqPython tools/prepare_usb_firmware.py
```

输出为本地 `resources/firmware/dt9837-ram.json`，不纳入源码仓库。运行核心时工作目录为项目根目录，GUI 启动器已遵循此约定。固件缺失、冷态驱动不匹配或运行态未在原 USB 端口出现时，会明确失败，不转为模拟输入。只加载 RAM，不改 EEPROM 或校准电位器。

在现有界面中选择“DT9837C · 真实 USB 输入”，可先点击“连接设备”，保持工作电源开启而不采样，此时应为绿灯。开始预览/记录时启动采集，本机用户在 2026-10-19 观察到橙色常亮，不将是否闪烁作为采集判断条件；“停止采集”停止数据流和当前记录，但保留 USB 连接与工作电源，返回绿灯。空闲时点击“断开设备”关闭工作电源并释放 USB。直接开始预览/记录也会自动连接。

PA4 测试使用 AI3、DC、IEPE 关闭、±10 V。连接时先置各输入为无激励 DC，开始采集时应用所选配置。采样率以核心返回的 PLL 名义值为准；电压偏差不自动补偿。只结束记录则继续预览；关闭活动采集的 GUI 保留核心和采集，关闭未采集的 GUI 则退出核心、断开设备。连接与采集分离后，已实测连接时零扫描、重复启停后保持连接，以及断开、重连。

2026-10-19 的实机短测已完成 195.3125、1000.115955 和四通道 105468.75 S/s，GUI 强制退出后的继续记录和重连也已通过。只有 AI3 接了 STM32 信号，其他通道的电气精度未检验。最高速首次同步读取出现过设备 FIFO 溢出，已改为预提交 8 笔异步读取并复测通过；错误记录保留实际终止原因，不伪装为正常完成。小时级、精密幅值/时基校准和核心意外退出恢复不在本次验证范围内。

同日卸载 QuickDAQ、Open Layers 及 OEM x86/x64 安装项后，物理拔插数采，从 WinUSB 冷态 PID 9839 开始，由 Rust 核心加载两段 RAM 固件并在原端口找到 PID 3998；随后上述三个采样率再次短测通过。最高速记录包含 572313 帧 × 4 通道，AI3 的 10 Hz 信号拟合为约 10.00039 Hz。该频率由设备名义采样率计算，不是外部时基校准。原厂参考资料仍保存在本地资源目录，运行测试未加载原厂 DLL。采集中拔线与小时级运行尚未实测。

### 原有模拟路径

Rust 独立模拟核心负责电压生成、AC 演示模型、24 位量化、原始记录和有界显示缓存。Qt 通过本机回环 TCP 控制核心并取得显示窗口；默认端口为 `47638`，连接信息和随机凭据保存在应用自管的 `.runtime/core.json`。

2026-10-16 已确认 **2 项 Rust 测试和 40 项 Python 定向测试通过，进程正常退出**。验证包含 GUI 被强制结束后的续录和重连、波形对照、调零、缓存上限及相关记录和界面回归；该结果不代表实机或小时级运行验证。

Rust 测试入口为 `cargo test --manifest-path core/Cargo.toml`，Python 测试位于项目根目录的 `tests/`，使用选定环境的解释器运行 pytest。按实际修改选择相关测试，纯文档修改无需重跑采集测试。

## 资料与后续工作

- 2026-10-19 用户确认：后续一般功能开发默认使用 Rust 独立软件模拟，先完善核心，暂不打磨前端。待示波器、信号发生器到齐后再开展精度验证与校准；无需数采或 STM32 持续连接。
  同日另按用户要求进行了一轮界面重绘（浅色 SaaS 风格、右侧可折叠参数区、底部命令条），只改 GUI 呈现与控件排布，不改变采集核心、记录格式或数据语义。
- [硬件背景与接口研究](technical-notes.md)、[Windows 原厂包与固件分析](windows-and-firmware.md)：后续独立 USB 开发的参考。
- 原厂手册、开源参考实现和设备照片在项目根目录的 `resources/` 下，仅本地保留，不随代码仓库发布。相关原厂样例和固件检查需要这些本地资料，缺失时相应测试会跳过；普通模拟流程不依赖它们。
- 个人交接记录、现场实验安排和实验室配置说明仅在本地保留。源码仓库只包含纯模拟示例配置，不包含实测记录或真实实验配置。

首版桌面软件完成打包后，再在根 README 中增加面向使用者的下载、安装和快速上手说明；内部安装包的具体工具与形式尚未选定。

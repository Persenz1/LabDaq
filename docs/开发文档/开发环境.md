# 开发环境与源码运行指南

[项目首页](../../README.md) / [文档中心](../README.md) / 开发者指南 (环境与源码)

---

LabDAQ 采用“**原厂 Open Layers C 驱动 + Rust 高性能采集核心 + Python / Qt 现代化桌面表现层**”的双进程解耦架构。本指南面向参与 LabDAQ 系统开发、核心扩展与自动化测试的工程技术人员，提供完整的开发环境配置、编译构建、源码调试与测试验证流程。

---

## 1. 系统架构与技术栈概览

```text
+------------------------------------------------------------------------------------+
|                                    表现层与接口层                                   |
|  - 桌面客户端: PySide6 (Qt 6.8+), PyQtGraph (高性能波形渲染)                       |
|  - 自动化接口: Python SDK (labdaq.api) & 本机无头 CLI (LabDAQ-api.exe)             |
+------------------------------------------------------------------------------------+
                                    ▲
                                    │ 本地 TCP 本地环回 (JSON-Lines, Token 鉴权)
                                    ▼
+------------------------------------------------------------------------------------+
|                                  Rust 采集核心                                      |
|  - 进程名: labdaq-core.exe (Rust 2024 Edition)                                     |
|  - 核心功能: 200,000 帧无锁环形缓冲区、双精度浮点原始流盘 (raw.f64)、DAC 连续供料  |
+------------------------------------------------------------------------------------+
                                    ▲
                                    │ 64 位 C-ABI 动态链接 (oldaapi64.dll / olmem64.dll)
                                    ▼
+------------------------------------------------------------------------------------+
|                              硬件与内核驱动层 (Windows)                             |
|  - 设备驱动: DT9837aK_x64.sys (运行态 PID 0x3998) / DT9837aLD_x64 (冷态 PID 0x9839)|
|  - 硬件设备: Data Translation DT9837C-BNC 动态信号采集仪                           |
+------------------------------------------------------------------------------------+
```

## 2. 开发环境准备 (Prerequisites)

### 2.1 基础系统与工具链要求

* **操作系统**：Windows 10 / 11 x64（推荐 PowerShell 7 作为主力终端）。
* **C++ 构建工具**：Visual Studio 2022 C++ 生成工具（Build Tools）或完整的 Visual Studio 2022，必须包含 **MSVC v143** 工具集与 **Windows 10/11 SDK**。
* **Rust 编译环境**：Rust 1.85+（支持 Rust 2024 Edition），采用 `x86_64-pc-windows-msvc` 目标工具链：
  ```powershell
  rustup default stable-x86_64-pc-windows-msvc
  ```
* **Python 运行环境**：Python $\ge 3.12$（支持标准 `python.exe`、`uv`、`fnm` 或 Conda 虚拟环境）。

### 2.2 Python 虚拟环境与依赖安装

在项目根目录下创建专用的虚拟环境并安装项目依赖：

```powershell
# 1. 创建 Python 虚拟环境
python -m venv .venv

# 2. 激活虚拟环境
.\.venv\Scripts\Activate.ps1

# 3. 安装依赖包
pip install --upgrade pip
pip install -r requirements.txt
```

核心依赖组件清单：
* `PySide6>=6.8`：现代化 Qt GUI 框架。
* `pyqtgraph>=0.14,<0.15`：工业级时域波形与频谱图表实时渲染引擎。
* `numpy>=2.0`、`scipy>=1.13`：工程数据换算、数字滤波（SOS IIR / 零相位滤波）与频域分析。
* `pytest>=8.0`：自动化回归测试套件。

## 3. 编译构建与源码运行 (Build & Run)

### 3.1 编译 Rust 采集核心

LabDAQ 的底层数据流泵与驱动交互封装在独立的 Cargo 包 `labdaq-core` 中。首次源码启动或修改 Rust 核心源码后，必须先执行编译：

```powershell
# 激活 MSVC 开发者环境（自动探测 VS 或 Build Tools 路径）
. .\tools\dev-env.ps1

# 编译 release 优化版本核心
cargo build --release -p labdaq-core
```

* **编译产物**：`target/release/labdaq-core.exe`。
* **注意事项**：若采集核心当前正被界面或后台进程占用，编译时会因文件锁定报错。请先关闭桌面客户端，并在任务管理器中确认无残留 `labdaq-core.exe` 进程后再行编译。

### 3.2 从源码启动桌面客户端

在激活的 Python 虚拟环境中，可采用以下两种方式启动系统：

```powershell
# 方式 A：使用项目根目录的快速启动脚本（自动查找 Conda/Python 环境并启动）
.\launch.ps1

# 方式 B：通过 Python 模块直接启动
python -m labdaq
```

### 3.3 免硬件模拟预览模式 (`--demo`)

在没有连接 DT9837C 物理数采仪的开发机上，可通过 `--demo` 参数启动带有软件波形生成器的模拟模式，用于验证界面交互、图表渲染与数据导出逻辑：

```powershell
python -m labdaq --demo
```

> [!NOTE] 演示模式边界说明
> `--demo` 参数仅供源码开发与界面回归调试使用。在生产发行版安装包中，系统将严格屏蔽模拟源，仅保留原厂物理设备连接与离线 HPF 历史文件分析功能。相关信号生成逻辑与开发边界请参阅 [数据与分析规范](../功能实现/data-and-analysis.md)。

## 4. 驱动集成与设备接入验证

### 4.1 原厂 Open Layers 驱动接入

LabDAQ 生产路径采用原厂 64 位 Open Layers C 动态链接库（`oldaapi64.dll`、`olmem64.dll`）：
* **直接加载机制**：Rust 采集核心（`core/src/vendor_input.rs`）在启动时直接通过动态库符号查找加载原厂 API，无需通过 Python ctypes 或第三方中间层。
* **驱动签名要求**：原厂驱动具备 Microsoft Windows Hardware Compatibility Publisher 正规数字签名认证，完全兼容 Windows 10/11 的“驱动程序强制签名”与 Secure Boot 安全启动机制。

### 4.2 设备状态转换与热插拔管理

1. **冷启动与运行态切换**：
   * 设备初次通电（未加载固件）时，硬件 USB 标识为冷启动态 `VID_0867&PID_9839`，由系统服务 `DT9837aLD_x64` 自动下发固件。
   * 固件加载完成后，设备在原 USB 端口重新枚举为运行态 `VID_0867&PID_3998`，由内核驱动 `DT9837aK_x64.sys` 建立通信。
2. **会话生命周期管理**：
   * 客户端点击“连接”仅打开 Open Layers 驱动句柄，硬件保持低功耗待机。
   * 点击“开始预览”或“开始记录”时，底层向硬件写入采样时钟寄存器并激活 24-bit Delta-Sigma ADC 连续流。
   * 点击“断开设备”将安全释放驱动会话独占句柄，便于其他第三方分析工具访问仪器；硬件保持 USB 物理连接与供电待机。

## 5. 自动化测试套件 (Automated Testing)

项目建立了分层自动化测试矩阵，覆盖 Rust 核心状态机、IPC 协议网络交互、Python 数据换算与 Qt 界面交互。

### 5.1 运行 Rust 核心单元与 IPC 测试

```powershell
# 运行 Rust 单元测试与端到端状态机测试
cargo test --manifest-path core/Cargo.toml
```

### 5.2 运行 Python 自动化回归测试

```powershell
# 运行全部 Python 定向测试套件
pytest tests/ -v

# 仅运行 Agent API 接口与命令行测试
pytest tests/test_api.py -v

# 仅运行数据导出与换算测试
pytest tests/test_recording.py -v
```

> [!TIP] Windows 下测试临时目录建议
> 在 Windows 终端运行 pytest 时，建议通过 `--basetemp` 指定项目内部独立的临时目录，避免多进程并发访问系统全局 `%TEMP%` 导致的权限争用：
> ```powershell
> pytest tests/ --basetemp=.task-tmp -q
> ```
